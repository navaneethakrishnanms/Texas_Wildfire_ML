# TDIS Tri-State Wildfire Ignition Model (rev5) — Team Handoff Package

**TX + NM + OK daily ignition risk.** This is a *research-validated, not-yet-
productionized* companion to the TX-only served model in the parent
`TDIS_Ignition/` folder. Package assembled 2026-09-23 for a team building the
live end-to-end scoring pipeline from here — **this package is data + model +
lineage code, not a runnable pipeline.** Read this whole file before writing
any code against it; several things below are load-bearing.

---

## 1. Why this model, honestly

**Design intent: train on diverse data (TX + NM + OK), operate on the
population of Texas.** The NM/OK rows are there to broaden the training
distribution (more fire regimes, more fuel/terrain/weather combinations), not
because NM/OK are deployment targets. That is exactly why the model's own
PRD rule says *"NM/OK never appear in any test set or metric"* — the
evaluation target has always been all-of-Texas.

**What the diversity bet buys, honestly stated:** on Texas accuracy metrics,
diverse training is a **wash** versus an identical TX-only recipe — validated
twice independently (before and after the ecoregion bug fix, §2): lift 2.38×
vs 2.39×, AUC-PR delta −0.003 (see §3). Diverse data neither helps nor hurts
measured TX accuracy. The case for it is robustness/coverage of the training
distribution, plus the option value of scoring neighboring states — not a
measured TX accuracy win. Do not claim otherwise in anything client-facing.

**NM/OK sanity check (2026-09-23, held-out 2024+ rows never used in
training):** the model does carry real skill into the states it trained on
but was never tested on — OK: AUC-PR 0.569 / AUROC 0.806 / lift 2.69×
(n=141,578); NM: AUC-PR 0.286 / AUROC 0.737 / lift 1.87× (n=30,072; weaker,
consistent with NM's HRRR-bbox-truncated weather coverage, caveat 3).
Matched-sample universes — a sanity check, not deployment validation.

## 2. Model lineage & what "v2" means

- **rev5** = the original tri-state candidate: 28 features (TX-only recipe's
  26 + `pop_density` + `fm100_5d_min`), trained on TX+NM+OK, **tested on
  TX-only 2024–2026** (NM/OK never appear in any test set or metric — a hard
  design rule, so nothing here claims NM/OK skill was ever measured).
- **A real bug was found and fixed (2026-09-23):** TX's `ecoregion_id`
  used a **locally re-indexed 0–19 scheme** (alphabetized TX ecoregion names)
  while NM/OK used the genuine **national EPA `US_L3CODE`**. These codes were
  incommensurate — the tri-state model could never have learned "this biome
  behaves the same in TX and NM," because the same biome had unrelated
  numeric codes in each state. Rebuilt via the same national spatial join
  NM/OK already used, across the full 1.7M-cell TX grid
  (`code/scripts/build_tx_ecoregion_national_full.py`,
  `code/scripts/fix_tx_ecoregion.py`).
- **"v2" = retrained on the corrected data.** `rev5_tristate_v2_seed{42,7,2026}.json`
  and `control_tx_only_v2_seed42.json` (the TX-only baseline, same corrected
  recipe, for honest comparison) are the ones to use. The original
  (pre-fix) `16_train_rev5.py`/`15_train_control.py` and their outputs are
  **not included here** — v2 supersedes them; only `_v2` scripts/models
  matter.
- **The fix did not change the conclusion.** Pre-fix tri-state delta was
  −0.0025 AUC-PR; post-fix it's −0.0029. Ruling out "the bug explains the
  null result" was the point of doing the fix.

## 3. Results — read the base rate before the AUC-PR

### Matched test set (TX-only, 2024–2026 held out), corrected data (v2)

| | Base rate | AUC-PR | AUROC | **Lift** (fair comparison) |
|---|---|---|---|---|
| control_v2 (TX-only, same recipe) | 31.5% | 0.7549 | 0.8312 | 2.39× |
| **rev5_v2 (TX+NM+OK)** | 31.5% | 0.7516 | 0.8302 | **2.38×** |

**Same base rate here (both trained/tested identically except NM/OK rows) →
AUC-PR IS directly comparable → tri-state is marginally behind, not ahead.**
This is the fair comparison; treat the delta as noise/null, not a real effect.

### ⚠️ What's missing: real-population validation

**DONE (2026-09-23)** — `model/realpop_res5_v2_results.json`, generated by
`code/nm_ok/20_realpop_res5_v2.py`: every TX res-5 cell × every day
2024-01-01..2026-07-29 (3,622,850 cell-days, 941 days, **true base rate
2.52%**), flare-excluded, corrected national ecoregion. Raw-score thresholds,

| Model | AUC-PR | AUROC | Lift | P/R @0.4 | P/R @0.5 | P/R @0.6 |
|---|---|---|---|---|---|---|
| control_v2 (TX-only) | 0.1082 | 0.7870 | 4.29× | .072/.608 | .099/.444 | .131/.314 |

### Calibration — REAL-POPULATION calibrator now included (use this one)

**`model/rev5_tristate_v2_isotonic_calibrator_REALPOP.joblib`** — isotonic,
fit on 2024–25 real-population res-5 outcomes, verified on the held-out 2026
real population: **ECE 0.288 → 0.00125**, calibrated mean prediction 0.0279 vs
true base rate 0.0283. This is the calibrator to apply before showing any
rev5 output as a probability — same protocol and quality as the served TX
model's calibrator (holdout ECE 0.0008). The earlier `_PRELIM` calibrator
(matched-sample temporal split) is kept for lineage only — do not use.

## 4. Feature set (28)

`rev4`'s 26 TX-only features (12 static, 6 calendar, 4 HRRR peak-weather,
drought, and 3 interaction terms `bp_x_vpd`/`whp_x_vpd`/`bp_x_drought`) **plus**:
- `pop_density` — WorldPop, unconstrained
- `fm100_5d_min` — gridMET 100-hr dead-fuel moisture, lag-2, 5-day trailing
  min (monotone-DOWN: drier fuel = higher risk)

`ecoregion_id` is now the **national EPA `US_L3CODE`** (see §2) — verify any
new code path assembling features uses `data/static/tx_ecoregion_national.parquet`
for TX, not the legacy local-scale column in
`data/static/static_master_tx_LEGACY.parquet` (kept only for lineage/diff
purposes — **do not train or score against it**).

## 5. Known caveats (read before deploying)

| # | Caveat | Detail |
|---|---|---|
| 1 | **No real-population validation** | See §3. Biggest open item. |
| 2 | **Preliminary calibrator** | Matched-sample-fit, not real-population-fit. See §3. |
| 3 | **HRRR weather bbox limit (v1)** | The 12Z HRRR archive this model trained on is TX-centered: covers all of TX, **~60% of NM** (eastern plains only), **~90% of OK**. Cells outside the bbox were **dropped**, not imputed, during training-table construction (`08_build_train_table_nm_ok.py`). A wider bbox re-pull would fix this — not done. |
| 4 | **~30% of the full TX bbox has no national ecoregion** | Expected, not a bug: the rectangular TX grid extends into Mexico (Big Bend/Rio Grande) and the Gulf of Mexico, which have no EPA US ecoregion code. These cells are correctly dropped from tri-state training (see `fix_tx_ecoregion.py` output). |
| 5 | **NM flare list — 98.6% reviewed, 1 known false positive** | `data/flares_nm.parquet` (1,956 cells) was visually checked against known basins: 98.0% Permian Basin, 0.6% San Juan Basin, ~0.8% plausible El Paso/Borderplex industrial corridor. **One cell (lat 33.5, lon −109.1, remote Catron County / Gila Wilderness) has no industrial explanation and is very likely a genuine wildfire location mis-flagged as a flare** — worth manually excluding from the flare list before it silently removes a real fire-prone cell from training. |
| 6 | **TX label times are ~87% imputed (daily-only)** | Inherited from the base TX pipeline — fine for a daily model, do not build sub-daily claims on this. |
| 7 | **Large re-pullable archives excluded from this package** | gridMET `fm100` daily archives (TX 4.0 GB + NM/OK 1.4 GB) needed to *extend* `fm100_5d_min` to new dates are **not** copied here (already baked into `data/train_tristate_v2.parquet` for existing dates). Canonical paths: `alphaearth_nds/TDIS_Forecast/data/gridmet_tx_full/`, `.../NM_OK_TexRev/data/gridmet_nm_ok/`. The 12Z HRRR forecast archive (tens of GB) is likewise excluded — re-pull via Herbie, same pattern as the TX-only model's README §6. |
| 8 | **`code/` is reference/lineage, not a runnable pipeline as-is** | See §7. |

## 6. What this team needs to build

This package gives you a validated model + the data that trained it. To turn
it into a live, deployable tri-state pipeline:

1. **Real-population scoring + calibration.** Score every TX+NM+OK cell
   (or a representative res-5 sample) across a real historical window with
   true labels, the way `../code/scripts/26_score_operational_realpop.py`
   did for the TX-only model. Refit the isotonic calibrator on that.
2. **Live weather ingestion for all three states.** Currently the peak-weather
   feature is TX-bbox-limited (caveat 3). Either widen the HRRR pull's bbox
   (Herbie/AWS `noaa-hrrr-bdp-pds`, same mechanism as the TX-only model,
   see `../docs/PRD_daily_ignition_section3_datareqs.md` §3.4-B) or accept
   partial NM/OK coverage and document it in the served product.
3. **Live drought ingestion for NM/OK**, not just TX. `code/nm_ok/05_build_drought_nm_ok.py`
   is the historical builder; there is no live/scheduled version yet (the
   TX-only model's `../code/scripts/fetch_live_drought.py` is TX-only — extend
   or replicate its pattern for NM/OK county FIPS).
4. **A self-contained scoring entrypoint**, analogous to
   `../serve/score_day.py`, but assembling all 28 features across three
   states' static masters + live weather/drought/fm100. Reuse
   `code/nm_ok/17_population_replay_v2.py`'s `score_day()`/`build_static()`
   logic as a starting point — it already does most of this for TX; extend it
   to include NM/OK cells.
5. **Fix the NM flare-list false positive** (caveat 5) before it's trusted
   the way the TX list is.
6. **Adapt hardcoded paths.** `code/nm_ok/*.py` and `code/scripts/rev4_pipeline.py`
   contain absolute paths back to the original `alphaearth_nds/TDIS_Forecast/`
   source repo (weather archives, county shapefiles, etc.) — they run as
   lineage/reference from that original location, not verbatim from this
   package. Treat `code/` as documented methodology to reimplement against
   this package's `data/`, not a drop-in pipeline (same convention as the
   TX-only model's `code/scripts/13`/`10`, which `../serve/score_day.py` was
   built to replace).

If the goal shifts back to "best possible TX-only accuracy," note that an
even stronger TX-only candidate than the currently-served model exists but
is **not packaged anywhere yet**: `rev4` (source repo:
`alphaearth_nds/TDIS_Forecast/Training_rev4_dailymax/RESULTS.md`) beats the
served model on every gate (matched AUC-PR 0.511 vs 0.494, real-population

only so it isn't lost. This tri-state package (`model_tristate/`) is for
teams that specifically need TX+NM+OK coverage, not for squeezing more
TX-only accuracy.

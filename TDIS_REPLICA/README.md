# Wildfire Risk Portal — Replica Demo

A working local replica of the TDIS portal's architecture (`tdis-portal-handoff-main/`
analyzed for tech stack), rebuilt to run our own 32-feature XGBoost wildfire
ignition model instead of TDIS's data, with a simulated live daily feed for
August 2026.

**This is an independent research demo, not an official TDIS product**, and
does not reuse any TDIS source code (the real `tdis-portal-frontend` /
`tdis-portal-api` / `tdis-portal-db` repos were never included in the handoff
package we received — only architecture docs, an empty schema, and a TRD PDF).

## What matches their real stack, and what's substituted

| Their component | Our replica | Why |
|---|---|---|
| React + Vite + **Mapbox GL JS** | React + Vite + **MapLibre GL JS** | MapLibre is the open-source fork of Mapbox GL JS — same API, zero account/token needed |
| FastAPI (`tdis-portal-api`) | FastAPI (`TDIS_REPLICA/api`) | Same framework |
| PostgreSQL + PostGIS + **pg_tileserv** (vector tiles) | Local **parquet files + a bbox/zoom-filtered FastAPI endpoint** | No Docker or native Postgres available in this environment — the endpoint reproduces the same "only send hexagons the viewport needs" behavior pg_tileserv provides |
| Databricks Bronze/Silver/Gold ingestion | `TDIS_REPLICA/ingestion/*.py` + `live_feed_daemon.py` | Runs our own trained model instead of TDIS's data sources |
| Real live data injection | **Simulated** — historical through 2026-07-31 is real (scored by our model on the actual dataset); August 2026 is a seasonal-average simulation, clearly labeled `"source": "simulated_live"` everywhere | No real-time weather/ignition feed is connected to this project |

## Architecture

```
TDIS_REPLICA/
├── ingestion/
│   ├── common.py                    # shared model-loading + H3 geometry helpers
│   ├── build_historical_snapshot.py # scores every H3 cell's latest known row -> historical_risk_cells.parquet
│   ├── build_live_august_feed.py    # pre-scores all 31 Aug days per cell -> live_august_staging.parquet
│   └── live_feed_daemon.py          # reveals 1 August day every N minutes -> live_feed_state.json
├── data/                            # generated by the scripts above (not committed data)
├── api/
│   ├── main.py                      # FastAPI, mirrors /api/v1/... surface + X-API-Key
│   └── requirements.txt
└── frontend/
    ├── src/App.jsx                  # top tabs, sidebar, legend, status strip (matches screenshot layout)
    ├── src/WildfireMap.jsx          # MapLibre GL hex risk layer + active-fire markers
    └── package.json
```

## How the data pipeline works

1. **`build_historical_snapshot.py`** — for every one of the 609,705 H3 cells
   in our TEXAS dataset, takes that cell's most recent available feature row
   (median cell has only ~2 rows across 13 years — this is a sparse
   fire+sampled-negatives dataset, not continuous daily coverage), scores it
   with `TEXAS/model_32feat_tuned.json` + the isotonic calibrator, and saves
   a queryable parquet (not a single giant GeoJSON file — 609k polygons is
   too large to ship to a browser in one response).
2. **`build_live_august_feed.py`** — for the same cells, builds a plausible
   August 2026 feature vector per cell by averaging that cell's own
   historical August observations (2014–2025) for weather/HRRR columns,
   keeping static features (elevation, LandFIRE, roads, `lat`/`lon`)
   unchanged, and computing calendar features (day-of-week, weekend/holiday)
   correctly for the real August 2026 calendar. All 31 days are pre-scored
   and written to a staging file — **nothing is published yet**.
3. **`live_feed_daemon.py`** — advances a `published_through` pointer by one
   day every `--interval-minutes` (default 2, so the full month reveals over
   ~62 minutes). The API refuses to serve any August date beyond that pointer.

## Honesty notes (read before treating this as more than a demo)

- **August 2026 risk scores are not a real forecast.** They're the trained
  model's output on a seasonal-climatology approximation of what August
  weather might look like per cell, not actual forecast weather. This is
  stated in the UI (`SIMULATED LIVE` badge) and in every API response
  (`"source": "simulated_live"`).
- **The historical map is a "standing hazard" snapshot, not daily history.**
  Because the underlying dataset is sparse per cell, "current risk" means
  each cell's most recent available row, which for many cells could be from
  months or years before 2026-07-31.
- **No PostGIS/pg_tileserv** — the bbox/zoom-filtered FastAPI endpoint is a
  reasonable stand-in but doesn't have real vector-tile caching, so very
  large viewports at high zoom may be slower than a production tile server.
